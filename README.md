# Jay Footware

A full-stack, responsive ukay-ukay shoe storefront created for PCFDS Task 4. The visual direction is inspired by bold skate/e-commerce layouts while using an original Jay Footware identity and design.

## Task 4 requirements included

- A separate, responsive **Admin Management interface** at `/admin.html`
- Admin tables for **Products/Inventory**, **Orders**, **Customers**, **Suppliers**, **Cashier Accounts**, and all user accounts
- At least five sample records in the main Task 4 management tables
- Use-case support for user accounts, product inventory, stock updates, low-stock alerts, supplier orders, delivery recording, customer records, sales, printable receipts, and printable/CSV reports
- Responsive CSS formatting, horizontal table scrolling on small screens, hover states, labels, and status badges
- Original responsive storefront made with HTML, CSS, and JavaScript
- Sign-in and sign-up pop-up
- Real server-side accounts, bcrypt password hashing, sessions, SQLite storage, rate limiting, and admin-only store records
- Optional verified Google sign-in
- A normalized relational database implementation connected to the supplied ERD: Role, User Account, Customer, Customer Address, Supplier, Supplier Address, Category, Brand, Product Condition, Shoe Size, Payment Method, Product, Product Variant, Inventory, Sales Transaction, Sales Item, Payment, Purchase Order, and Purchase Order Item

## Database and ERD

The supplied Oracle ERD has been implemented in SQLite for a portable school prototype. Oracle `NUMBER`, `VARCHAR2`, and `TIMESTAMP` types are represented using SQLite `INTEGER`/`REAL`, `TEXT`, and timestamp text values. Primary keys, foreign keys, unique constraints, checks, and normalized relationships are retained. Product cards and the three admin tables are generated by SQL joins across these normalized tables—not hard-coded in HTML.

## Run locally

1. Install Node.js 20 or newer.
2. Open a terminal in this folder.
3. Run:

```bash
npm install
cp .env.example .env
npm start
```

4. Open `http://localhost:3000`.

### Admin login

- Username: `admin`
- Initial password: `Yojinn`

Signing in as admin redirects to the dedicated Admin Management interface. The admin route also checks the server session and redirects unauthorized users back to the storefront.

For deployment, immediately change `ADMIN_PASSWORD` in `.env`, delete `data/jay-footwear.db` once, and restart so the admin is seeded with the new password. Never commit `.env` or the database.

## Enable Google sign-in

Google sign-in requires your own Google Cloud credentials; no application can safely include somebody else's credentials.

1. Go to Google Cloud Console → APIs & Services → Credentials.
2. Configure the OAuth consent screen.
3. Create an **OAuth client ID** of type **Web application**.
4. Add `http://localhost:3000` and your deployed HTTPS site URL as Authorized JavaScript origins.
5. Copy the client ID into `.env`:

```env
GOOGLE_CLIENT_ID=your-client-id.apps.googleusercontent.com
```

6. Restart the server. The Google button appears automatically.

## Important deployment notes

- Replace `SESSION_SECRET` with a long random value.
- Use HTTPS and set `NODE_ENV=production`.
- The default in-memory session store is suitable for a school/local prototype. For multi-instance production deployment, switch to a persistent session store.
- Shopping-bag and newsletter controls are interface prototypes; accounts and admin access are server-backed.
